# 시의 결 · 한국 시 감정 분석

한국 근대시 15편에서 감정 표현을 찾고, 계산 결과를 작품 해석과 비교하는 정적 웹앱입니다. HTML, CSS, JavaScript로 동작하며 로그인이나 API 키가 필요하지 않습니다.

## 1. 웹앱 주소와 사용법

- [웹앱 주소](https://ysg0306.github.io/korean-poetry-emotion-map/) — GitHub Pages 설정 및 첫 배포 성공 후 이용할 수 있습니다.
- [GitHub 저장소](https://github.com/ysg0306/korean-poetry-emotion-map)
- **시 읽기**: 서가에서 작품을 고르면 본문, 감정 비율, 레이더, 해석, 행별 차트와 추천이 바뀝니다. 본문이나 막대를 누르면 감지 근거가 보입니다.
- **전체 비교**: 15편의 감정 비율을 히트맵으로 비교하고 작품으로 이동합니다.
- **내 시 분석**: 본문을 입력하면 비율, 레이더, 행별 막대그래프, 감지 근거와 추천을 보여줍니다. 입력은 브라우저 안에서 처리됩니다.
- **분석 검증**: 실제 계산과 해석이 다른 세 사례를 확인합니다.
- 휴대폰에서는 한 열로 표시합니다. 긴 시의 차트와 넓은 비교표는 해당 영역 안에서 옆으로 넘깁니다.

로컬 실행은 저장소 루트에서 `python -m http.server 8766`을 실행한 뒤 `http://localhost:8766/`을 엽니다. 배포 파일은 이미 포함되어 있어 별도 빌드가 필요하지 않습니다.

## 3. 감정 범주와 분석 방법

| 감정 | 정의 | 대표 사전 항목 수 |
|---|---|---|
| 기쁨 | 즐거움이나 만족으로 마음이 밝아지고 활기를 느끼는 정서다. | 16 |
| 슬픔 | 상실이나 고통을 마주하며 마음이 가라앉는 정서다. | 23 |
| 그리움 | 부재하는 사람이나 장소, 시간을 다시 만나고 싶은 정서다. | 12 |
| 사랑 | 대상과 가까워지고 아끼며 함께하고 싶은 정서다. | 15 |
| 희망 | 어려움 속에서도 더 나은 미래를 기대하고 나아가려는 정서다. | 15 |
| 분노 | 부당함이나 침해에 반발하고 맞서려는 정서다. | 14 |
| 불안 | 불확실한 상황이나 위협을 의식해 긴장하고 염려하는 정서다. | 14 |
| 평온 | 갈등과 긴장이 잦아들어 안정과 여유를 느끼는 정서다. | 17 |

총 126개 대표 항목에 활용형과 옛 표기 패턴을 연결했습니다. 각 행에서 긴 표현을 먼저 찾고, 겹친 표현을 중복 계산하지 않습니다. 감정 비율은 `해당 감정 감지 수 / 전체 감지 수 × 100`입니다. 소수점 반올림으로 표시 합계에 작은 오차가 생길 수 있습니다. 감지되지 않으면 임의의 비율을 만들지 않고 안내합니다.

지배 정서는 계산 비율이 가장 높은 범주이며 동률은 함께 표시합니다. 해석에서 읽은 정서는 별도로 표시하고 계산 비율에 섞지 않습니다. 추천은 감정 비율 벡터의 코사인 유사도 상위 3편입니다. 입력 본문과 일치하는 수록 작품은 추천에서 제외합니다. 행별 누적 막대의 높이는 감지 횟수이며 정수 눈금에 맞춰 표시합니다.

교수님 예시는 기능과 과제 구성을 참고했습니다. 현재 분석 엔진과 화면은 별도로 구현했습니다. 사전은 개발 명세서에 정리한 96개 항목에서 126개로 늘렸습니다. ‘위로’, ‘외로움’, ‘싸늘한 이마/먼지’ 등 표현과 활용형을 보완하고, 방향의 ‘위로 올라간다’, 닭의 울음, ‘비웃지’ 같은 오탐 및 「통곡」의 특정 부정 표현을 제외했습니다. 변경 이유와 대상 작품은 [사전 보완 기록](data/emotion-lexicon-additions.json)에 있습니다.

## 4. 문학적 검증 사례

분석 수치는 실제 엔진을 실행해 기록했습니다. 개선 제안과 실제 적용한 수정을 구분했습니다.

### 빼앗긴 들에도 봄은 오는가 — 밝은 봄의 단어가 작품 전체의 기쁨을 뜻할까?

나는 이 시의 중심 정서를 슬픔과 울분으로 보았다. 중간에는 봄 들판을 반기는 표현이 나오지만, 마지막에는 땅을 빼앗긴 현실로 돌아오기 때문이다. 따라서 기쁨이 가장 높게 계산된 결과만으로 시 전체가 즐겁다고 설명하기는 어렵다고 생각한다.

원인: 현재 계산은 감지 단어를 한 번씩 같은 무게로 센다. 중간에 반복되는 반가움과 가뿐함은 잘 잡지만, 마지막 문장이 앞의 풍경을 다시 보게 만드는 역할은 점수에 반영하지 못한다. 분노라는 직접적인 단어가 없으면 현실에 대한 울분도 놓칠 수 있다.

개선: 연별 감정 흐름과 마지막 연의 의미를 함께 설명하고, 표현된 기쁨과 작품 전체의 상실감을 구분해서 보여 주는 방법이 필요하다. 마지막 행의 가중치를 높이는 방법도 검토할 수 있지만 모든 시가 결말에서 주제를 요약하는 것은 아니므로 다른 작품에서도 확인해야 한다.

적용 상태: 해석과 원인을 기록했다. 임의로 결말 가중치를 주는 수정은 적용하지 않았다.

### 싸늘한 이마 — 위로를 바라는 말과 실제로 위로받은 상태의 차이

나는 이 시에서 위로받은 상태보다 위로를 바라는 마음이 더 크다고 보았다. 산꽃이나 귀뚜리가 곁에 있으면 좋겠다는 말은 지금 외롭다는 상황을 함께 보여 준다. 그래서 기쁨과 평온이 감지되어도 화자의 외로움이 해결되었다는 뜻으로 받아들이기는 어렵다고 생각한다.

원인: 사전은 위로·기쁨·즐거움의 등장 자체는 잡지만, 그것이 현재 상태인지 바람인지 나누지 않는다. 또 싸늘한 이마를 맑아지는 감각으로 읽은 분류가 평온 점수에 들어가므로, 긍정 비율을 곧 만족한 마음으로 받아들이면 해석이 달라진다.

개선: 조건 표현 ‘있으면’이 걸리는 범위를 표시하고, 현재 느끼는 정서와 바라는 정서를 나누어 설명할 수 있다. 긍정 단어를 모두 지우거나 슬픔으로 바꾸기보다는 현재 감정과 소망의 층위를 구분하는 쪽이 적절하다고 보았다.

적용 상태: 조건문 처리 방식은 개선안으로 기록했다. 기쁨·평온 단어의 범주나 점수를 바꾸지는 않았다.

### 통곡 — ‘그리워 울음이 아니다’에서 부정된 그리움을 센 경우

나는 이 시의 울음을 그리움보다 현실에 대한 답답함과 항의로 보았다. 화자가 하늘이 그리워 우는 것은 아니라고 말하고, 이어서 이 땅에서 두 발을 뻗을 수 없는 상황을 설명하기 때문이다. 그래서 이 구절의 그리움을 그대로 세면 화자가 부정한 이유를 감정에 포함하게 된다고 생각한다.

원인: 단순 부분 문자열 매칭은 그리워라는 시어 뒤의 ‘울음이 아니다’를 읽지 않고 그리움 한 번을 더했다. 울음 자체는 다른 행에서도 실제로 드러나므로, 부정문이 있다는 이유로 슬픔까지 모두 지우는 것도 맞지 않는다.

개선: 그리움 시어 바로 뒤에 ‘울음이 아니다’ 또는 ‘울음이 아니라’가 이어지는 경우 그리움 감지를 제외하는 제한적인 규칙을 추가했다. 긍정 문장인 ‘하늘이 그리워’에서는 그리움이 계속 감지되는지도 확인한다.

적용 상태: 해당 부정 구문의 예외 규칙을 적용하고 같은 본문으로 수정 전후를 다시 계산했다.


「통곡」은 같은 본문에서 그리움 감지 1회가 0회로 줄었습니다. 보완 전 비율은 슬픔 57.1%, 그리움 14.3%, 분노 28.6%이고 보완 후는 슬픔 66.7%, 그리움 0%, 분노 33.3%입니다. 나머지 두 사례의 계산 규칙은 바꾸지 않았습니다. 자세한 실제 수치와 시구는 앱의 ‘분석 검증’ 및 [검증 보고](docs/작품해석_문학적검증_초안.txt)에 있습니다. 재현용 코드와 입력은 [스냅샷](docs/validation-snapshots)에 보관했습니다.

## 5. 한계와 개선 방향

단어 빈도는 문학적 정답이나 정확도 점수가 아닙니다. 반어, 조건, 소망, 문맥에 따라 같은 표현의 의미가 달라질 수 있습니다. 「통곡」의 예외 규칙은 특정 구문만 처리하며 일반적인 부정문 이해 기능은 아닙니다. 향후 연별 문맥과 현재 감정·바라는 감정을 구분하는 방법을 검토할 수 있습니다.

본문은 현대 표기 읽기본으로 초간본과 표기 차이가 있습니다. 출처 링크와 정리 기록을 함께 확인해야 합니다. 15편의 자동 검사와 내장 브라우저 검사는 통과했으며, 실제 배포 주소의 PC·휴대폰 접속과 Chrome·Edge·Safari 전체 호환성은 배포 후 확인할 항목입니다. 휴대폰 첫 화면에서 필수 정보까지 이동하는 길이는 추가로 개선할 수 있습니다.

### 파일 구성과 데이터 재생성

- `index.html`: GitHub Pages 진입점
- `preview/`: 화면, 스타일, 분석·시각화 코드와 생성된 데이터
- `data/`: 작품 선정, 본문 판본, 사전 보완, 해석·검증 자료
- `docs/`: 대조 기록과 분석 재현 자료
- `tools/`: 데이터 생성 및 검사 도구

데이터를 바꿨다면 Python 3와 Node.js로 아래를 순서대로 실행합니다. 초기 보완 전 스냅샷은 덮어쓰지 않습니다.

```sh
python tools/build_preview_data.py
node tools/build_literary_validation.cjs
node tools/check_preview_data.cjs
```

`build_preview_data.py`는 루트 진입점도 갱신합니다. 내부 감정 식별자 `key`는 과제 명세의 `k`에 대응합니다. 임시 수집 파일, 생성 PDF, 테스트 화면 캡처와 환경 변수 파일은 Git에서 제외합니다.

## 6. AI 도구 사용 내역

ChatGPT(Codex)를 화면 구성과 JavaScript 코드 작성·수정, 감정 사전 보완, 공개 본문 자료 탐색과 현대 표기 대조 보조, 15편 해석 초안, 실제 분석 결과에 근거한 검증 사례 정리, 자동·브라우저 검사, README 작성에 사용했습니다. 시 본문을 AI의 기억으로 생성하지 않고 출처 자료를 사용했습니다. 외부 해설을 참고한 경우 링크를 붙였습니다.

작품 해석과 검증 사례는 AI가 제안한 초안을 바탕으로 직접 검토·수정하여 최종 정리했습니다.
